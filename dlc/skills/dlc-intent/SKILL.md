# dlc-intent — 착수 전 검토

요구사항을 쓰기 전에 "이걸 왜 만드는가"를 확정한다. 산출물 `intent.md`는 뒤 단계에서 범위 판단의 기준이 된다. express·bugfix 프로파일에는 이 단계가 없다.

공통 절차는 [../dlc/references/protocol.md](../dlc/references/protocol.md), 출처 규칙은 [../dlc/references/grounding.md](../dlc/references/grounding.md)에 있다. 스크립트 위치 `<skills>/dlc/scripts/dlc.py`의 뜻은 protocol.md의 "스크립트 위치" 절을 따른다. 아래는 이 단계에서만 다른 것이다.

## 읽을 것

- `state.md`의 `description`. 사용자의 최초 설명이며 `[desc]` 출처다.
- `docs/dlc/codebase.md`(brownfield일 때). 기존 시스템의 제약이 타당성 판단의 근거가 된다.

## 질문 주제

depth는 `state.md`의 값을 따른다(full은 standard). standard면 5~8개, minimal이면 2~4개. 아래 순서로 빈 곳을 채우되, `description`에서 이미 답이 나오는 주제는 묻지 않는다.

| 순위 | 주제 | 묻는 것 |
|---|---|---|
| 1 | 문제 | 지금 무엇이 안 되거나 불편한가. 누가 겪는가. 안 만들면 무엇이 계속 일어나는가 |
| 2 | 대상과 가치 | 첫 사용자는 누구인가. 그 사람에게 무엇이 달라지는가 |
| 3 | 성공 지표 | 성공을 무엇으로 재는가. 목표값·기한·측정 방법 |
| 4 | 범위 안 | 첫 릴리스에 반드시 들어가는 것 |
| 5 | 범위 밖 | 요청받았지만 이번에 하지 않는 것. 나중으로 미루는 이유 |
| 6 | 제약 | 기한, 예산, 반드시 써야 하거나 쓸 수 없는 기술, 규제 |
| 7 | 타당성 위험 | 가장 불확실한 것 하나. 기술적으로 검증이 필요한 지점 |
| 8 | 대안 | 만들지 않고 해결하는 길(구매, 수작업, 기존 기능 확장)을 검토했는가 |

minimal이면 1~4번만 묻는다.

성공 지표 답이 측정 불가능하면("더 편하게", "빨라지게") 후속 질문으로 숫자·기한·측정 방법을 받는다. 후속 질문은 protocol.md 6단계의 번호 체계를 따른다.

질문 파일은 작업 폴더의 `intent-questions.md`. 형식과 답변 검사는 protocol.md.

## 산출물 골격

### intent.md

```markdown
# 의도

## 문제
지금 무엇이 안 되고 누가 겪는지 2~4문장. [desc] [Q1]

## 대상과 가치
| 대상 | 지금 | 이후 | 출처 |
|---|---|---|---|
| 창고 관리자 | 재고를 엑셀로 대조한다 | 화면에서 실시간 수량을 본다 | [Q2] |

## 성공 지표
| 지표 | 목표값 | 기한 | 측정 방법 | 출처 |
|---|---|---|---|---|
| 재고 불일치 문의 건수 | 주 10건 → 2건 | 출시 후 8주 | CS 티켓 태그 집계 | [Q3] |

## 범위
### 안
- SKU 단위 실시간 수량 조회. [Q4]

### 밖
- 입출고 등록. 기존 ERP가 계속 담당한다. [Q5]

## 타당성
| 관점 | 판단 | 근거 | 출처 |
|---|---|---|---|
| 기술 | 가능. 기존 PostgreSQL에 재고 테이블이 있다 | codebase.md 구조 절 | [practice] |
| 일정 | 3주 안에 가능 | 화면 1개, API 2개 | [Q6] |
| 위험 | ERP 동기화 지연이 5분을 넘으면 실시간의 뜻이 흐려진다 | | [Q7] |

## 가정과 열린 질문
- ERP 동기화 주기는 1분으로 가정한다. 확인 필요. [assumption]
```

- 성공 지표 표의 행은 네 칸(목표값·기한·측정 방법·출처)이 모두 채워져야 한다. 하나라도 비면 산출물을 쓰지 않고 후속 질문으로 돌아간다.
- `## 범위`는 `### 안`·`### 밖` 소절을 둔다. 사용자가 고르지 않은 선택지를 "밖"으로 옮기지 않는다(grounding.md).

## 완료 기준

- `dlc.py check intent`가 OK: 필수 절 여섯 개, 질문 파일의 모든 답변과 `Looks correct`, 가정 절.
- 성공 지표에 측정 불가능한 항목이 없다.
- 사용자가 승인 게이트에서 승인했다(protocol.md 10단계). 승인 뒤 `dlc.py approve intent`.

## 출력 언어

사용자 대면 출력과 산출물은 한국어. 코드, 식별자, 경로, 명령은 원문 유지.
