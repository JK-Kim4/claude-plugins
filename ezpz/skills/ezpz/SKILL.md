# ezpz — 그림책 설명 문서

어떤 조건에서 무엇이 어떻게 보이는지를 **그림 한 장 + 짧은 이야기 몇 줄**의 펼침면으로 한 장면씩 넘겨 보게 만드는 문서다. 조직에 확인을 요청하거나, 개발 밖의 사람에게 동작을 설명할 때 쓴다.

이 스킬로 만드는 문서는 doc-writing 스킬과 그 규칙 파일의 구조·문장 규칙(`이 문서에 대해` 상자, 고정 섹션 이름, 해요체 금지 등)을 따르지 않는다. 다만 **사실 확인 규칙(`~/.claude/rules/document-writing.md` 2절)은 그대로 지킨다.** 그림책은 쉬워 보여서 숫자 하나가 틀리면 그대로 믿고 퍼진다.

## 파일

| 파일 | 쓰는 때 |
|---|---|
| `templates/book.html` | 새 문서의 출발점. 복사해서 자리표시 `{…}`를 채운다. 그림 부품이 모두 들어 있다 |
| `reference/pictures.md` | 장면 그림을 고를 때. 무엇을 설명하나 → 어떤 그림, 색의 뜻, 그림 규칙 |
| `examples/README.md` | 승인된 예시 목록과 각 예시에서 볼 점. **예시가 있으면 쓰기 전에 하나는 끝까지 읽는다.** 없으면 틀의 주석과 자리표시를 따른다 |
| `check/check.py` | 게시 전 점검. 0건이어야 게시한다 |

예시는 모양·밀도·말투를 맞추는 데만 쓴다. 예시의 용어·숫자·장면 구성을 새 문서로 옮기지 않는다.

## 독자

조직 구성원 전체(기획·운영·CS·개발)가 함께 본다. 기본 독자는 **개발을 모르는 사람**이고, 개발자가 볼 내용은 장면마다 `개발팀 참고` 칸 하나에만 둔다. 개발팀 참고 칸을 지워도 문서가 이해돼야 한다.

## 책 골격

순서는 고정이다. 할 말이 없는 쪽은 뺀다(표지, 정해 주세요, 숫자와 근거는 빼지 않는다).

| 쪽 | 하는 일 | 그림 |
|---|---|---|
| 표지 | 질문형 제목 · 한 줄 소개 · **지금 확인이 필요한 N가지** 카드(누르면 그 장면으로) · "마지막 장에서 N가지를 정해 주세요 →" · 기준 시각 도장 | 문서 전체를 대표하는 그림 하나 |
| 1쪽 용어 | 헷갈리는 값·개념의 정체를 정의 | 값 카드, 칸 격자 |
| 2쪽 규칙 | 결과를 정하는 판정 단계, 단계마다 보는 값과 갱신 주기 | 문 또는 흐름 |
| 장면 쪽(반복) | 조건 조합 하나 → 결과 하나. 해당 수, 판정 | 목업 + 조건 칩 |
| 비교 장면 | 같아 보이는데 결과가 다른 두 경우를 나란히. 보통 핵심 질문이 여기 | 나란히 |
| 이야기 장면(선택) | 제보·사고 한 건에 시간순으로 일어난 일 | 시간표 |
| 이력 장면(선택) | 그동안 정한 것·안 정한 것 | 지금까지 |
| 정해 주세요 | 조직이 정할 질문. 질문마다 지금 상태 한 줄 + 선택지별 결과 | 없음 |
| 숫자와 근거 | 접힌 상자. 대상, 장면별 수, 계산식, 대조 결과, 조회 시각, 출처 | 없음 |

## 절차

1. **핵심 질문과 확인할 것 정하기.** 독자가 이 책을 덮고 알아야 할 것 하나, 조직이 확인하거나 정해야 할 것 N가지를 먼저 적는다. N가지가 표지 카드가 되고, 정해 주세요 장의 질문이 된다.
2. **사실 확인.** 장면을 나누기 전에 원천을 본다. 코드에서 조건식과 갱신 주기를, 데이터에서 장면별 수를 확인한다.
   - 운영 데이터는 읽기 전용 복제 DB(replica)로만 조회한다(이 환경에서는 dabi). 원본(primary)은 쓰지 않는다.
   - 장면별 수를 더하면 대상 전체 수와 같아야 한다. 어느 장면에도 안 들어가는 것(판매 중이 아님 등)도 근거에 수를 적는다.
   - 계산으로 판정했으면 실제 화면 결과와 한 번 대조한다(예: 운영 페이지 카드 500장과 계산값 일치).
   - 그림에 넣을 사례 하나하나(카드의 `18/16`, 칸 격자의 칸 수, 시간표의 시각)도 원천에서 다시 읽는다. 확인 못 한 것은 `미확인`으로 적고, 추측으로 채우지 않는다.
3. **용어 정하기.** 독자가 헷갈릴 값마다 이름을 하나 정한다.
   - **값의 정체가 이름에 드러나게 한다.** ❌ `어드민 현원`(무엇을 세는지 모름) ✅ `클럽 인원 카운터`, `다음 모임 남은 자리`.
   - 조직이 이미 쓰는 말(슬랙, 어드민 화면 라벨)이 있으면 그 말을 쓴다.
   - 처음 나오는 곳(대개 1쪽)에서 한 문장으로 정의하고, 이후 모든 제목·칩·카드·질문에서 같은 이름만 쓴다.
4. **장면 나누기.** 결과를 정하는 조건들의 조합마다 장면 하나. 장면마다 해당 수와 판정을 정한다.
   - 판정 알약은 셋 중 하나: `ok` "의도대로 동작" / `ask` "조직 확인 필요: {묻는 말}" / `bad` "의도와 다름: {무엇이}". 규칙대로인데 제보된 건은 `ok` "오류 아님: 규칙대로 동작".
   - `ask`와 `bad` 장면이 표지의 '지금 확인이 필요한 N가지'가 된다(`ask-c` 해 색, `bad-c` 장미 색). 카드는 **서로 다른 문제마다 하나**이고, 해당 장면으로 링크한다. 이미 카드가 있는 문제와 원인이 같은 이야기 장면·다시 보기 쪽은 카드를 따로 만들지 않는다. 이력 장면의 판정 알약은 넣어도 되지만 카드를 만들지 않는다.
   - 같은 묶음을 다른 화면에서 다시 보는 쪽은 장면 번호를 새로 매기지 않는다. 쪽 번호는 `5쪽 · 장면 2를 사장님 앱에서`, 수는 `214건 / 장면 2와 같은 예약`처럼 쓰고, 근거에 따로 세지 않았다고 적는다.
5. **그림 고르기.** `reference/pictures.md`의 표로 장면마다 그림을 고른다. 화면이 있는 주제면 목업, 없으면 흐름·문·칸 격자·시간표.
6. **쓰기.** `templates/book.html`을 작업 파일로 복사하고 채운다. 아래 '글 규칙'을 지킨다.
7. **개발팀 참고 칸.** 장면마다 그 장면을 정하는 필드·조건식·실제 값을 적는다. 아래 '개발팀 참고' 참고.
8. **정해 주세요.** 1단계의 N가지를 질문 카드로 만든다. 아래 '정해 주세요' 참고.
9. **점검.** 이 스킬 폴더의 `check/check.py`로 `python3 -I <스킬 폴더>/check/check.py <파일>`을 돌려 0건이 될 때까지 고친다. 그다음 '사람이 볼 것'을 직접 확인한다.
10. **렌더해서 보기.** 밝은 화면·어두운 화면을 전체 길이로 찍어 본다(아래 '렌더').
11. **게시.** 아래 '게시와 파일'.
12. **답장.** 링크, 독자가 확인할 N가지 요약 한 줄씩, 확인 못 한 것, 문서 범위 밖에서 발견한 것(티켓 제안)을 짧게.

## 글 규칙

- **이야기 줄(`.lines p`)은 한 줄에 한 문장, 장면당 2~3줄.** 합니다체로 쓴다. 이유·배경이 길면 그림이나 개발팀 참고 칸으로 옮기고, 그래도 남으면 뺀다.
- **제목은 결과를 말하는 짧은 말.** 해요체 입말을 쓴다("자리가 남았는데 사라졌어요", "클럽은 문 세 개를 지나요"). 표지 제목만 질문형("꽉 찬 클럽은 큐레이션에서 어떻게 보일까요?").
- **문장마다 주어와 대상을 쓴다.** "왼쪽은 클럽 인원 카운터가 정원과 같아서 큐레이션에서 사라집니다." 앞 줄에 기대는 '그', '이', '해당'을 쓰지 않는다.
- **숫자는 정확히, 단위와 함께.** `73곳`, `12/5 모임`, `30분마다`. "많은", "자주" 대신 수를 쓴다.
- **조건을 떼지 않는다.** "자리가 0이면 맨 아래로 보냅니다"를 "맨 아래로 보냅니다"로 줄이지 않는다.
- **비교 장면은 '왼쪽/오른쪽' 대신 라벨 이름으로 부른다.** 좁은 화면에서는 두 그림이 위아래로 쌓여 '왼쪽'이 틀린 말이 된다. ❌ "왼쪽은 …" ✅ "픽업이 아침 7시 30분인 예약은 …"
- **굵게는 한 줄에 한 구절.** 그 장면의 결과에만. 틀은 `<b>`를 제목 글꼴로 바꿔 보여 준다(본문 글꼴에 굵은 글씨가 없음).
- **예시 줄(`.example`)은 구체 사례 하나**, 이름과 숫자를 넣어 한 문장.
- **코드 이름은 개발팀 참고 칸에만.** 본문에서는 하는 일로 부른다("상품 목록 갱신", "큐레이션 쿼리").

## 개발팀 참고

개발자가 "어떤 값이 이 조건 판정에 쓰이는지" 바로 찾게 하는 점선 칸이다.

- **한 항목에 정보 하나.** 회색 라벨 한 줄(`.k`) + 값 한 줄(`.v`). 필드 두 개를 한 줄에 넣으면 좁은 화면에서 줄바꿈이 틀어진다.
- 라벨은 무엇인지 한국어로 짧게(`1번 문 조건`, `오른쪽 우선권`, `갱신 주기`), 값은 필드명·조건식·실제 값·위치(서비스와 함수) 중 하나.
- 코드는 `<code>`로 감싼다. 틀의 CSS가 줄바꿈을 막고 넘치면 가로로 스크롤한다.
- 장면 칸에는 **그 장면 사례의 실제 값**을 적는다(`seatCount 21 = capacity 21 → 제외`). 규칙 쪽 칸에는 조건식·위치·갱신 주기를 적는다.
- 칸 제목은 `개발팀 참고: 이 장면을 정하는 값`처럼 무엇이 들었는지 말한다. 한 칸에 3~11항목.

## 정해 주세요

- 질문은 **그것만 읽어도 이해되게** 쓴다. 어느 화면, 어떤 대상인지 질문 안에 넣는다. ❌ "이 클럽은 어떻게 할까요?" ✅ "다음 모임 남은 자리가 0인 클럽은 주제별 큐레이션에서 어떻게 보여야 하나요?"
- `지금:` 한 줄에 현재 동작을 수와 함께 적는다.
- 선택지는 2~3개, 각각 **고르면 무엇이 어떻게 되는지** 한 문장. 사용자가 요청하지 않으면 추천을 표시하지 않는다. 정하는 건 조직이다.
- 표지 버튼 "N가지를 정해 주세요"의 N은 질문 수와 같아야 한다. 표지 확인 카드 수와 질문 수는 달라도 된다(문제 하나에서 정할 것이 둘 나올 수 있다).

## 렌더

샌드박스가 막으면 그 명령만 샌드박스 밖에서 실행한다. 앵커(`#p4`)를 붙여 찍으면 스크롤 위치 때문에 빈 화면이 찍히므로 앵커 없이 전체를 찍는다.

```
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CHROME" --headless=new --disable-gpu --hide-scrollbars --user-data-dir=<scratchpad>/chrome \
  --window-size=1200,<전체 높이> --virtual-time-budget=4000 --screenshot=<scratchpad>/pb.png "file://<단독 HTML>"
# 어두운 화면: --force-dark-mode --blink-settings=preferredColorScheme=0 추가
# 좁은 화면: --window-size=500,<높이> (headless는 500px보다 좁게 못 찍음)
```

`<전체 높이>` 재기: 단독본 사본 끝에 높이를 제목에 적는 스크립트를 붙여 DOM을 뽑는다. 같은 폭으로 잰다.

```
cp <단독 HTML> <scratchpad>/h.html
printf '<script>document.title=document.documentElement.scrollHeight</script>' >> <scratchpad>/h.html
"$CHROME" --headless=new --disable-gpu --user-data-dir=<scratchpad>/chrome --window-size=1200,800 \
  --virtual-time-budget=4000 --dump-dom "file://<scratchpad>/h.html" | grep -o '<title>[0-9]*'
```

긴 캡처를 나눠 볼 때는 `sips -c <높이> <폭> --cropOffset <y> 0`으로 자른다. 위쪽부터 자를 때 `y`를 0으로 주면 무시되고 가운데가 잘리므로 1을 준다. `sips`도 샌드박스 밖에서 돌려야 할 수 있다. 자른 이미지는 한 장씩 열어 본다.

볼 것: 첫 화면이 비어 있지 않은가, 글자가 선·테두리에 닿지 않는가, 개발팀 참고 값이 한 줄씩 떨어지는가, 칸 격자 칸 수가 맞는가, 어두운 화면에서 글자가 보이는가, 좁은 화면에서 펼침면이 위아래로 쌓이는가.

## 사람이 볼 것 (점검 스크립트가 못 잡는 것)

- 그림 속 숫자와 사례 값을 원천 조회 결과와 한 줄씩 맞춰 봤는가
- 장면별 수의 합 = 대상 수인가
- 한 개념에 이름이 둘 이상이거나, 한 이름이 두 뜻으로 쓰이지 않았는가
- 개발팀 참고 칸을 가려도 장면이 이해되는가
- 표지 숫자가 맞는가: '확인이 필요한 N가지'의 N = 카드 수, 버튼의 N = 질문 수(숫자로 쓰면 점검 스크립트도 본다)

## 게시와 파일

- **artifact 원본**: 틀처럼 doctype·`<html>`·`<head>` 없이 `<title>`부터 시작한다. 작업 폴더(scratchpad, 사용자가 정하면 그곳)에 두고 Artifact 도구로 게시한다(새 artifact면 `icon: "book"`). 디자인은 이 틀이 정하므로 따로 꾸미지 않는다.
- **로컬 단독본**: 사용자가 로컬 파일을 원하면 원본 위에 `<!doctype html><html lang="ko"><head><meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`를 씌우고 `<style>` 뒤에 `</head><body>`, 끝에 `</body></html>`을 닫는다. 렌더 확인도 이 단독본으로 한다.
- 다시 고칠 때는 같은 파일을 고쳐 같은 artifact로 다시 게시한다.

## 함정 (실제로 겪은 것)

- **재고만 보고 "자리 남음"이라고 했다가 두 번 틀렸다.** 판매 가능 수량은 예약·우선권 몫을 빼고, 판매하지 않는 회차를 제외해야 한다. 결과를 정하는 계산식을 코드에서 그대로 확인하고, 화면 결과와 대조한다.
- **칩에 `seat` 클래스를 붙였다가** 칸 격자 스타일(`aspect-ratio:1`)이 먹어 칩이 큰 네모로 그려졌다. 수식 클래스는 컴포넌트 접두사(`ch-`, `fs-`, `msg-`, `win-`)를 쓴다.
- **개발팀 참고 한 줄에 필드 여러 개**를 넣었다가 줄바꿈이 틀어졌다. 라벨/값 한 줄씩.
- **"어드민 현원"처럼 화면 위치로 지은 이름**은 무엇을 세는지 몰라 모호하다는 지적을 받았다. 값의 정체로 이름을 짓는다.
- **앵커를 붙여 headless 캡처**하면 빈 화면이 찍힌다.
