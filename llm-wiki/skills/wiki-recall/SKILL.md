# wiki-recall

`${CLAUDE_SKILL_DIR}`는 Claude Code가 스킬을 로드할 때 이 스킬 디렉터리의 절대 경로로 치환한다. 치환되지 않는 환경(`npx skills add`로 설치한 Codex·Gemini)에서는 이 SKILL.md가 있는 디렉터리를 뜻한다.

위키를 **읽는** 쪽. **핵심 원칙: 찾는 것보다 가리는 것이 어렵다.** 텍스트는 grep이 찾아준다. 어려운 건 걸린 수십 건 중 무엇을 지금도 믿을 수 있는지다.

**경계** — 문서를 쓰거나 고치지 않는다. 답하다가 틀린 서술을 발견하면 고치지 말고 **알린다**(고치는 건 `wiki-lint`의 미결 판정). **조회는 위키 안에서 끝난다** — `git`·이슈 트래커·원본 저장소를 여는 것은 사용자가 명시적으로 요구할 때만 하는 별개 작업이다.

- 무엇을 믿을 것인가(층별 우선순위·낡음 판정·0건 대응) → `references/reading.md`
- 규칙의 실측 근거 → `references/rationale.md`

## 1. 좁힌다

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/recall.py <질의> [질의...]
python3 ${CLAUDE_SKILL_DIR}/scripts/recall.py <질의> --lines        # 매치 줄까지
python3 ${CLAUDE_SKILL_DIR}/scripts/recall.py <질의> --limit 30
python3 ${CLAUDE_SKILL_DIR}/scripts/recall.py <질의> --root ~/other # 다른 위키
python3 ${CLAUDE_SKILL_DIR}/scripts/recall.py --recent             # 질의어 없이 최근 문서
```

위키 루트는 `~/.config/llm-wiki/config.json`의 `root`에서 얻는다. 없으면 스크립트가 알려주고 멈춘다. 질의어를 여러 개 주면 전부 포함한 문서를 먼저 올린다. 결과는 **층별로 묶여 날짜와 크기가 붙어** 나온다 — 이 셋이 판정의 재료다. 항상 `raw/`는 제외한다.

**"가장 최근" 류 질문은 `--recent`로.** 시간을 묻는 질문에는 검색할 키워드가 없다. `--recent`는 `log.md` 꼬리(위키 전체 기준, 프로젝트 스코프 없음)와 날짜 있는 최신 문서(스코프 있음)를 낸다. 둘을 섞어 읽지 않는다. 날짜 없는 문서는 빠진다.

**현재 프로젝트를 먼저 놓는다.** 실행 위치의 경로 조각을 문서의 `project`와 대조해 순위를 올린다(거르지는 않는다 — 나머지는 `↗` 표시). `--project <이름>`으로 지정, `--all`로 끈다. 답할 때 "이 프로젝트 기준"인지 "위키 전체 기준"인지 밝힌다.

**한국어로 먼저 검색한다.** 0건이면 `references/reading.md`의 순서(질의어 줄이기 → 표현 바꾸기 → 식별자로)로 다시 시도한다.

### 읽는 순서 — 싼 것부터

**이 스킬의 이득은 읽을 문서를 줄이는 데서 나온다.**

1. **`--lines`로 매치 줄을 먼저 본다.** 그것으로 답이 되면 파일을 하나도 열지 않는다.
2. 부족하면 **상위 1~2건만** 연다. 목록의 `KB`를 보고 고른다.
3. **`⚠무거움`(30KB 이상)은 통째로 열지 않는다.** 필요한 절만 찾아 읽는다.
4. **`⚠ 너무 넓다`(60건 초과)가 뜨면** 목록을 훑지 말고 질의를 좁힌다.

**총예산: 답 1건당 `recall.py` 1회 + 문서 2~3건.** 넘겨야 하면 넘기되 왜 넘기는지 밝힌다("층이 엇갈려 양쪽을 봐야 한다"). 조회가 그냥 읽는 것보다 비싸지면 이 스킬은 손해다.

## 2. 층을 안다

| 층 | 무엇인가 | 무엇을 물을 때 |
|---|---|---|
| `retrospectives/` | **평가·교훈의 정본** | "왜 그렇게 했나", "무엇을 배웠나" |
| `sessions/` | **그 시점의 사실 기록** | "무슨 일이 있었나", "어떤 커밋·이슈였나" |
| `projects/*/00-STATUS.md`·진척 문서 | **현재 상태** | "지금 어디까지 됐나" |
| `knowledge/` | 확정 지식 | 프로젝트를 넘어 재사용되는 것 |
| `sources/` | 외부 원문(불변) | 원문 인용이 필요할 때 |

**평가는 세션이 아니라 회고에서 가져온다.** 세션 문서의 "결정과 교훈"은 회고가 있으면 그쪽으로 위임돼 있다.

## 3. 날짜를 반드시 본다

**세션 문서는 그 시점의 기록이지 현재 상태가 아니다.** 규칙 넷:

- **날짜 없이 단정하지 않는다.** `날짜없음` 문서는 언제 기준인지 알 수 없다(`projects/`에 특히 많다).
- **`→ 2026-..-.. 확인:` 주석이 있으면 그것이 최신 판정이다.** `wiki-lint`가 남긴 것으로, 원문보다 나중 사실이다. 그대로 믿고 다시 검증하지 않는다.
- **미결·예정 서술(`미착수`·`미검증`·`미결`·`착수 전`)은 "그 시점 기준"으로 답한다.** 판정 주석이 없으면 거기서 멈추고, 낡았을 가능성이 답에 중요하면 확인이 필요하다고 알리고 `wiki-lint`를 가리킨다.
- **위키 밖 도구는 사용자가 명시적으로 요구할 때만.**

## 4. 답한다

- **근거를 링크로 단다.** 어느 문서의 어느 시점 서술인지.
- **여러 층이 엇갈리면 엇갈린다고 말한다.** 임의로 하나를 고르지 않는다 — 대개 시점 차이이고 그 차이가 답의 일부다.
- **`raw/`를 인용하지 않는다.** 참조 표면은 `sessions/`다.
- **못 찾으면 못 찾았다고 한다.** 추측으로 메우면 다음 사람이 그것을 위키에 적힌 사실로 읽는다.
