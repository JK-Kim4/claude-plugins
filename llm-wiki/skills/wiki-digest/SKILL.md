# wiki-digest

AI 세션 원본(JSONL)을 사람이 읽는 위키 문서로 가공한다. 지식베이스에서 가장 큰
유입 경로다 — 세션은 사람이 못 읽는 형식이라 원료→가공본 2단계가 필요하고,
그 변환이 이 스킬의 전부다. 마크다운 문서는 이미 읽을 수 있으므로 여기 오지 않는다.

**경계**: JSONL만 다룬다. 회고 작성, 외부 자료 수집, 코드 저장소 문서 편입은 범위 밖이다.

문서 규격(프론트매터·5섹션 구조·작성 규칙)은 `references/document-shape.md` 를 읽는다.

## 전제 둘

**진행 중 세션은 가공하지 않는다.** 기록이 미완이라 결말이 없는 문서가 나온다.
최근 60분 내 수정된 파일이 여기 해당하고, 지금 이 세션 자신도 마찬가지다.
탐색 스크립트가 이미 걸러내지만, 사용자가 특정 파일을 지목하면 확인하고 알린다.

**원본은 이동하지 않는다.** 복사만 한다. Claude Code 는 `~/.claude/projects/` 의
파일로 세션 재개를 지원하는데, 옮기면 그 기능이 조용히 깨진다.

## 1. 위키 루트 확보

```bash
python3 <skill>/scripts/locate.py root
```

경로를 출력하면 그대로 쓴다. 종료 코드 3 이면 설정이 없는 것이고, 스크립트가 후보를
같이 보여준다. **사용자에게 확인받고** 기록한다:

```bash
python3 <skill>/scripts/locate.py root --set <경로>
```

한 번 기록하면 다음부터 묻지 않는다. 이 스킬은 경로를 본문에 담지 않는다 —
머신마다 위키 위치가 다르고, 경로가 박히는 순간 다른 머신에서 못 쓴다.

## 1-b. 수집 대상 관리 — 프로젝트가 늘었을 때

**탐색(2단계)은 목록이 필요 없다.** cwd 로 파생하거나 전체를 훑으므로 새 프로젝트가
생겨도 자동으로 잡힌다. 목록이 필요한 쪽은 **수집**이다 — Claude Code 는 세션을 기본
30일 후 지우므로, 나중에 가공하고 싶어질 것을 미리 지켜둬야 한다. 전량 보존은 수백 MB 가
계속 쌓이므로 관심 있는 것만 고른다.

```bash
python3 <skill>/scripts/locate.py collect                    # 현재 목록
python3 <skill>/scripts/locate.py collect --add ~/repo       # 프로젝트 추가
python3 <skill>/scripts/collect.py --dry-run                 # 무엇이 복사될지
python3 <skill>/scripts/collect.py                           # 수집 실행
```

목록에 없는 프로젝트라도 막히지 않는다. 가공 직전에 그 파일만 확보하면 된다:

```bash
python3 <skill>/scripts/collect.py --file <원본 경로>
```

### 새 프로젝트 자동 등록

사람이 기억해서 등록하는 방식은 반드시 새는다 — 잊은 프로젝트는 30일 뒤 되살릴 수 없다.
그렇다고 대화 중에 감지하는 것도 못 미덥다. 이 스킬이 불릴 때만 동작하는데, **정작
위험한 건 이 스킬을 한 번도 안 부른 프로젝트**이기 때문이다.

그래서 수집 자체가 발견하게 한다:

```bash
python3 <skill>/scripts/collect.py --auto-add                    # 세션 3개 이상이면 등록
python3 <skill>/scripts/collect.py --auto-add --min-sessions 5   # 임계 조정
```

세션 파일에 기록된 `cwd` 를 읽어 실제 경로를 얻으므로 슬러그를 역산할 필요가 없다.
임계를 두는 이유는 한두 번 열어본 디렉터리까지 보존하면 용량만 늘기 때문이고,
**컨테이너 디렉터리는 제외한다** — 안에 프로젝트가 여럿 든 곳(`~/workspaces` 등)을
등록하면 하위를 전부 흡수해 사실상 전량 수집이 된다.

cron/launchd 에 `--auto-add` 로 걸어두면 사람이 아무것도 안 해도 새 프로젝트가
며칠 안에 등록된다. 이미 수집한 원본은 건너뛴다.

## 2. 대상 세션 찾기

```bash
python3 <skill>/scripts/locate.py sessions              # 실행 위치 기준
python3 <skill>/scripts/locate.py sessions --new-only   # 아직 가공 안 된 것만
python3 <skill>/scripts/locate.py sessions --cwd <경로> # 특정 프로젝트
```

**실행 위치가 곧 대상 지정이다.** 프로젝트 저장소 안이면 그 프로젝트 세션(워크트리 포함)을,
위키 안이나 홈이면 전체를 잡는다. 사용자가 어디서 부르든 의도에 맞게 좁혀진다.

대상이 여럿이면 목록을 보여주고 어느 것인지 확인받는다. 최근 것 하나를 임의로 고르지 않는다
— "방금 그 세션"이 사용자 머릿속에서는 명확해도 목록에서는 두세 개가 후보다.

## 3. 추출 — 파일을 통째로 읽지 않는다

```bash
python3 <skill>/scripts/extract.py <파일> --max-chars 40000
```

원본은 수십 MB 다. 실측으로 15MB 원본이 44KB 로 줄었다. 통째로 읽으면 컨텍스트가
망가지고 그 세션에 대해 아무것도 못 쓰게 된다. 스크립트가 도구(Claude/Codex)를
자동 판별해 사용자 발화 전량 + 어시스턴트 응답 표본 + 식별자 후보(커밋 해시·브랜치)만 낸다.

**건너뛸지는 발화 수가 아니라 내용으로 판단한다.** 요청 하나에 충실한 답이 나온
1왕복짜리 세션도 남길 값어치가 있고, 반대로 "계속"·"ok"만 스무 번 오간 세션은
발화가 많아도 남길 게 없다. 남길 게 없는 세션은 문서를 만들지 말고 건너뛴 사실만
보고한다 — 빈 문서는 검색 결과를 흐리기만 한다.

`--max-chars` 는 예산이지 정확한 상한이 아니다. 세션이 아주 길면 두 번 나눠 뽑기보다
예산을 늘려 한 번에 보는 편이 서사가 끊기지 않는다.

## 4. 회고 대조

같은 작업의 회고가 위키에 있는지 본다.

```bash
rg -l '<트랙 키워드>' <위키루트>/retrospectives
```

- **있음** → "결정과 교훈"은 회고 링크로 위임하고 세션 고유 사실만 남긴다
- **없음** → 결정·교훈을 세션 문서에 직접 적는다

평가와 교훈의 정본은 회고다. 같은 내용을 두 문서에 복제하면 나중에 갈라지고, 그때
어느 쪽이 맞는지 판단할 근거가 없다.

## 5. 문서 작성

`references/document-shape.md` 의 규격대로 쓴다. 핵심만 옮기면 — 프론트매터에
`session_file` 을 반드시 남기고(재생성 가능 여부의 근거다), 본문은 5섹션 서사형,
전사에서 확인된 사실만, 45줄 내외.

기존에 같은 세션 문서가 있으면 새로 만들지 않고 갱신한다.

## 6. 검증

```bash
python3 <wiki-bootstrap>/scripts/survey.py <위키루트>
```

깨진 링크가 늘지 않았는지 본다. 늘었다면 대개 `raw/` 경로에 링크를 걸었거나
존재하지 않는 회고를 참조한 것이다.

## 일괄 가공

수십~수백 건을 한 번에 처리해야 할 때가 있다(예: 형식을 바꿔 전량 재생성).
**한 세션에 다 끝나지 않으므로 재개 가능하게 만든다.**

**상태는 위키 루트의 `.digest/` 에 둔다.** 대화가 끊겨도 다음 세션이 이어받을 수 있어야
하는데, 그러려면 상태가 대화가 아니라 디스크에 있어야 한다. 규약:

```
<위키루트>/.digest/
├── README.md               지금 무슨 작업이 진행 중이고 어떻게 이어받는지
├── worklist.tsv            대상 전체 — 상태 ⇥ 문서경로 ⇥ 원본경로
└── <원본 백업>/            착수 전 문서 전량 사본
```

**`README.md` 를 반드시 쓴다.** 새 세션은 이 대화를 모른다. 무엇이 진행 중이고, 어디까지
됐고, 어떤 판단이 이미 확정됐는지가 그 파일에 없으면 처음부터 다시 논의하게 된다.

**진행 여부는 기록보다 실제 문서로 판정한다.** 완료 목록 파일은 중간에 어긋날 수 있으므로,
매번 문서를 열어 규격 충족 여부로 잔여를 다시 센다. 기록은 참고용이다.

작업을 시작하기 전에 **`.digest/README.md` 가 이미 있는지 본다.** 있으면 진행 중인
배치이므로 새로 설계하지 말고 거기 적힌 규약을 따른다.

한 번에 5~10건씩 끊어서 처리하고 매 묶음마다 사용자에게 진행 상황을 보고한다.
전량을 조용히 돌리면 형식이 어긋났을 때 수백 건을 되돌려야 한다.

**이미 문서가 있는 세션을 재생성할 때는 기존 문서를 함께 읽는다.** 추출은 표본이라
긴 세션의 뒷부분이 잘리는데, 기존 문서에는 그때 전량을 보고 뽑은 정보가 응축돼 있다.
원본만 보고 다시 쓰면 조용히 정보가 사라진다 — 실제로 확인된 실패다. 원본에서는
사용자 발화의 원문과 온도를, 기존 문서에서는 결론과 미해결 목록을 가져와 합친다.
기존 문서는 덮어쓰기 전에 통째로 백업해 둔다.

## 테스트

```bash
python3 -m unittest discover -s <skill>/tests
```

외부 의존 없이 stdlib 만 쓴다. **스크립트를 고치면 여기부터 돌린다** — 이 스위트의
상당수가 실사용에서 터진 버그의 회귀 방지라, 통과하지 않으면 같은 사고가 재발한다.

## 마무리

만든 문서 경로와 건너뛴 세션(있으면 이유와 함께)을 보고한다. 위키 루트에 `log.md` 가
있으면 이번 턴 항목을 하나 추가한다 — 파일당이 아니라 턴당 하나다.
