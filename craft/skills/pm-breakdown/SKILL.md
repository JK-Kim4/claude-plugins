# pm-breakdown — 전략을 작업 단위로

확정된 전략·기획 문서를 받아 기술팀이 착수할 수 있는 이슈로 만든다. 2026-08-19 리텐션·유입 작업(#150~#155)에서 실증된 흐름의 후반부다.
작성 규격 정본은 `prd-ticket-writing` 스킬이다 — 시작 시 Skill 도구로 로드한다 (pm-skills(Apache 2.0)의 PRD 구성·유저 스토리 INVEST·수용 기준 그룹핑·우선순위 적용성 필터/거부 규약을 이 저장소 이슈 관례와 결합한 증류본).

## 원칙

- **입력이 먼저다** — 확정된 전략 문서(및 리뷰 반영 상태)를 받는다. 없으면 `marketing-strategy` 등 선행 스킬을 안내하고 중단한다.
- **각 단계는 사용자 검토 게이트로 끝난다.** 알림과 실행을 같은 턴에 합치지 않는다.
- 미확정 결정은 임의 확정하지 않는다 — "열린 질문"으로 모으고, 화면 결정은 비교 목업 + AskUserQuestion 으로 하나씩 확정한다. 용어는 한 줄 정의 먼저 (§35).

## 단계

### 1. 목표 분리 + 우선순위

- 3분류: **기술 목표(T)** — 기술팀 작업 / **운영 목표(O)** — 비개발 작업 / **보류** — 해제 조건 명시.
- 우선순위는 ICE 개략 추정 — 정량 데이터 없으면 RICE 금지(점수 날조 금지), 추정임을 명시하고 계측 후 재산정 조건을 적는다.
- 각 기술 목표에 성공 지표(가설이면 가설 표기)를 붙인다.

### 2. 에픽·티켓 정의 문서

- 에픽 아래 티켓: 유저 스토리("페르소나·행동·이유" 형식, 기능이 아니라 사용자 목표 단위) + 레이어(FE/BE) + 의존성 + Given/When/Then 수용 기준(핵심 실패 경로 포함 — 예: 기록 0 사용자의 빈 카드 방지).
- 실행 순서는 **하나의 순서로 합쳐 현재 위치를 표시**한다 (§40). 필수 경로와 선택 항목을 섞지 않는다.
- 문서는 `docs/research/YYYY-MM-DD-*-workplan-prd-draft.html`.
- 게이트: 문서 검토 + **산출 목적지 확인** (이 프로젝트 = GitHub Issues, Jira 아님) + 열린 질문 해소.

### 3. GitHub 이슈 발행

- **gh 계정 확인 먼저** — 활성 계정이 JK-Kim4 인지 (`gh auth status`, 회사 계정이면 `gh auth switch -u JK-Kim4`).
- 기존 이슈 관례를 실측해 따른다 (#144~#148 참조): `[PRD]` 부모(착수 게이트 blockquote + 결정 정본 링크 + Problem/Solution/User Stories) + `[n/N]` 슬라이스(Parent / What to build / 실측 의무 / 주의 / Acceptance criteria 체크리스트), 라벨 `enhancement`.
- 슬라이스의 "실측 의무" 절에는 이 프로젝트 규율을 번안해 넣는다: 문서 명시값 실측(§4), 계측·가드의 화면 경로 전수 확인(§12), 신규 상태의 기존 판정 규칙 명세(§37), 알려진 죽은 소스 회피.
- 미확정 사항은 부모에 명시하고 해당 슬라이스에 착수 전 재확인 게이트를 건다. 확정되면 이슈 **본문**을 갱신한다(코멘트가 아니라 본문 — 다음 사람은 본문만 읽는다).
- 범위 추가 시 슬라이스 번호를 `[n/N]` 전체 재조정하고 부모 솔루션 목록도 갱신한다.

## 종료 기준
