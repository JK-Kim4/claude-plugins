# 지시서 틀

`<…>`를 채우고, 해당 없는 절은 지운다(단 「기록·보고」「금지」「멈춤 조건」은 지우지 않는다). 보통 50~100줄. 길어지면 공통 규칙을 `briefs/<묶음>-공통-규칙.md`로 빼고 「먼저 읽기」에서 가리킨다.

```markdown
# 지시서 <단계 ID> — <할 일 한 줄> (<범위 한정: 예 「운영 전환 제외」>)

보낸 쪽: `<오케스트레이터 이름>` (<YYYY-MM-DD HH:MM> KST) / 받는 쪽: `<하위 세션 이름>` / Jira: <키 또는 없음>
승인: 사용자 <MM/DD HH:MM> 「<원문>」 — <이 원문이 허락한 범위>. **<범위 밖: 예 운영 전환은 dev 확인 뒤 따로 승인>.**
작업 폴더: `<절대 경로>/` (아래 상대 경로는 이 폴더 기준)

> **기록 규칙: 단계마다 체크리스트 공유 DB `log`(url `<아티팩트 URL>`, step="<단계 ID>", by="<하위 세션 이름>", at은 `date '+%Y-%m-%dT%H:%M:%S+09:00'`)에 같은 턴에 기록. 실제 시작 `start`, 멈춤 `block`, 끝 `done`.**

## 사용자 지시 (원문)
- <MM/DD HH:MM> 「<원문>」
- <계획 승인과 실행 승인을 구분해 적는다>

## 먼저 읽기
1. <공통 규칙·선례 결과 파일·이전 지시서>
2. <코드: 저장소·브랜치(origin/<branch>)·파일 경로·줄>
3. <설정·정의: k8s 경로, 인프라 정의>

## 지금 사실 (<MM/DD HH:MM> KST 조회)
| <대상> | <값> | <값> |
|---|---|---|
- 오케스트레이터 추정은 「추정, 확인할 것」으로 표시.

## 정해진 것
| 항목 | 값 |
|---|---|
| <구조·데이터 접근·결과 고정·켜기 조건·파일 충돌 회피 등> | <값 — 사용자 결정이면 원문 시각> |

## 할 일
1. [준비] <작업 트리: `origin/<base>`에서 `<worktree 경로>`, 브랜치 `<이름>`>
2. [준비] <백업: `backups/<YYMMDD>-<일>/…`>
3. [준비] <구현·테스트: 현재 동작 고정 테스트 → 테스트만 커밋 → 변경 → 같은 기대값 통과. 단위 테스트는 스텁>
4. [준비] <PR 생성(머지하지 않음)·대조표>
5. INBOX에 「<단계> 준비 끝」 한 줄 → **기다린다.**
6. [실행, 「<단계> 실행」을 받은 뒤] <순서. 정각 회차 사이 등 시각 제약>
7. [감시] <회차마다 볼 것: 기대값, 중복 0, 오류·재시작 0. dev면 시험 결과 확인으로 끝(대기 감시 없음)>

## 산출물
- `results/<단계 ID>.md`: 요약 3줄 · <비교 표> · 바꾼 파일 · 테스트·빌드 · 커밋·PR · <되돌리는 명령> · 확인 못 한 것
- <`results/<단계 ID>.diff`>

## 멈춤 조건
- <관찰 가능한 사실: 테스트 실패, 기대값을 바꿔야 통과, 운영 렌더 차이, 재시작, 2번 처리·남음, 지시서에 없는 새 의존> → 멈추고 INBOX에 `[대기]`.

## 되돌리기
- 기준: <무엇이 보이면>
- 방법: <백업·revert PR로 어떻게>
- <사용자 위임이 있으면: 사용자 <MM/DD HH:MM> 「<원문>」 → 묻지 말고 되돌린 뒤 INBOX + herdr로 `<오케스트레이터>`에 보고. 없으면: 멈추고 [대기]>

## 금지
- <운영 쓰기 범위 밖 전부: main·태그·운영 설정·운영 DB primary>, force push, 수동 실발송, 시크릿·개인정보 출력.
- `aws`·`kubectl`·`gh`·`git fetch/push`·`herdr`·로컬 소켓 빌드는 샌드박스 밖. 샌드박스 밖 실행이 막히면 설정을 묻지 말고 돌릴 명령을 스크립트로 만들어 경로를 INBOX에 남긴다(오케스트레이터가 돌림).
- 커밋 끝: <저장소 관례의 attribution 줄>

## 기록·보고
- 결과 `results/<단계 ID>.md` + 체크리스트 `log`를 같은 턴에.
- `reports/INBOX.md`에 한 줄씩: <준비 끝 / 실행 끝 / 회차마다 / 판정>. 형식 `- YYYY-MM-DD HH:MM KST [<이름>] <단계> … 컨텍스트 NN%`. 결정이 필요하면 `[대기]`.
- herdr로 오케스트레이터에게 직접 보고하지 않는다(되돌리기를 실행했을 때만 예외).
- 사실로 적는 것은 직접 읽거나 실행해 확인한 것만. 못 본 것은 「미확인」과 확인 방법. 「경로 없음」「불가」는 시도한 명령과 오류 원문을 같이.
- 컨텍스트가 60%를 넘으면 진행 중 단계만 끝내고 INBOX에 `[인계 필요]`.
- 답과 보고는 한국어.

## 합의 대조 (오케스트레이터가 보내기 전 확인)
| 합의·결정 (원문 시각) | 지시서 반영 위치 |
|---|---|
| <…> | <절 이름> |
- 새 의존·동작: <없음 / 있으면 사용자 결정 원문>
```
