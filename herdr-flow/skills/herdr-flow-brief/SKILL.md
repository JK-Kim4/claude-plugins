# 하위 세션에 일 맡기기

`<skills>`는 이 스킬 디렉터리의 부모다(로컬 설치면 `~/.claude/skills`, 플러그인 설치면 `<plugin>/skills`). `herdr-flow/`는 공용 규칙·스크립트만 담은 형제 디렉터리다.

먼저 읽을 것: `<skills>/herdr-flow/shared/rules.md`(전부), `shared/folder-layout.md`. 지시서 틀: `reference/brief-template.md`.
스크립트: `<skills>/herdr-flow/scripts/` (`spawn.sh`, `send.sh`, `ctx.sh`). 모두 샌드박스 밖에서 실행한다.

## 1. 맡길 일 정하기

| 항목 | 정하는 법 |
|---|---|
| 단계 ID | 체크리스트 단계 ID(`S6.12`). 없으면 계획에 단계를 먼저 추가(체크리스트 재게시)하고 쓴다 |
| 범위 | 계획의 **묶음 하나**가 한 지시서다. 독립 묶음은 지시서·세션을 나눠 동시에 |
| 받는 세션 | 새 세션이 기본. 기존 세션을 쓰려면 `ctx.sh`로 재서 50% 미만일 때만 |
| 모델 | 사용자가 지정하면 그대로. 아니면 구현·조사·배포 `claude`. 설계 토론은 `herdr-flow-debate`(없으면 이 스킬로 `fable` 세션) |
| 승인 범위 | 사용자 원문과 시각. 실행 단계가 승인 전이면 **준비/실행을 나눈다**(3절) |

사용자가 이 일을 지시한 원문이 대화에 없으면(오케스트레이터가 계획에서 꺼낸 일이면) 범위에 사용자 결정이 필요한 것이 있는지 본다. 있으면 지시서를 쓰기 전에 그 하나만 묻는다(`rules.md` 7절).

## 2. 사실 다시 읽기

지시서의 「지금 사실」 표에 들어갈 값은 쓰기 직전에 원천에서 다시 읽는다: 저장소 브랜치·SHA, PR 상태, 배포 태그·이미지, 큐·크론·설정 값, 운영 데이터(읽기 전용 replica). 표에 조회 시각을 붙인다. 앞 지시서·결과 파일의 값을 그대로 옮기지 않는다. 오케스트레이터가 추정한 대응(어느 함수가 어느 스케줄에 붙었는지 등)은 「추정, 확인할 것」으로 표시해 하위 세션이 확인하게 한다.

## 3. 지시서 쓰기

`reference/brief-template.md`를 채워 `<작업 폴더>/briefs/<단계 ID>-<짧은 이름>.md`에 쓴다. 지킬 것:

- **사용자 지시는 원문 그대로** 인용하고 시각을 붙인다. 「계획 승인」과 「실행 승인」을 구분해 적는다.
- **준비/실행 분리**: 실행(운영 쓰기, 머지, 대상 제거, 배포)이 아직 승인 전이면 `[준비]`(읽기·백업·PR 생성·대조표)는 바로, `[실행]`은 오케스트레이터가 「<단계> 실행」을 보낸 뒤에만 한다고 적는다. 준비가 끝나면 INBOX에 「준비 끝」 한 줄을 쓰고 기다리게 한다.
- **되돌리기**: 기준(무엇이 보이면)과 방법(백업에서 어떻게)을 적는다. 사용자가 되돌리기를 미리 맡겼으면 그 원문을 붙이고 「묻지 말고 되돌린 뒤 보고」로. 맡긴 적 없으면 「멈추고 [대기]」.
- **멈춤 조건**은 관찰 가능한 사실로 쓴다(테스트 실패, 기대값을 바꿔야 통과, 운영 렌더 차이, 재시작, 2번 처리 등).
- **기록·보고 절**은 틀의 문장을 그대로 둔다(INBOX 한 줄, 체크리스트 `log` 같은 턴, 60% 인계, herdr 직접 보고 금지).
- 비밀 값·개인정보는 쓰지 않는다. 위치(Secret 이름, 파일 경로)만.

### 보내기 전 점검 (지시서 끝 「합의 대조」 표로 남긴다)

1. **합의 대조**: 이 작업에서 사용자와 합의한 설계·결정(체크리스트 `decisions`, 인계 문서 결정 표)을 줄마다 지시서 어디에 반영됐는지 대조한다. 빠졌거나 어긋나면 고친다.
2. **새 의존·동작 점검**: 지시서가 전에 없던 저장소·Redis·테이블·외부 서비스·동작을 들이는지 본다. 들이면 지시서에서 빼고 사용자에게 선택지로 먼저 묻는다. 현재 동작 그대로 유지는 묻지 않는다.
3. **저장소 관례 대조**: 고칠 저장소의 `AGENTS.md`·`CLAUDE.md`·컨벤션 문서와 지시서의 이름·구조·커밋·배포 방식이 맞는지(배포 관례 스킬·문서가 있으면 그것).
4. **사용자 기준 원문**: 사용자가 정한 기준(심각도·판정 기준 등)을 자기 말로 바꿔 쓰지 않았는지.

## 4. 세션 기동

```bash
<skills>/herdr-flow/scripts/ctx.sh <작업 약어>-          # 기존 세션 재활용 시·인계 기준 확인
<skills>/herdr-flow/scripts/spawn.sh <이름> <claude|fable|sonnet|codex> [워크스페이스] [cwd]
```

- 워크스페이스는 비우면 오케스트레이터와 같은 곳. cwd는 비우면 오케스트레이터 패널의 cwd(프로젝트 메모리가 cwd 기준이라 바꾸지 않는다).
- `idle 대기 실패`가 나오면 화면을 보고 사용자에게 알린다. 시작 확인 화면에 임의로 답하지 않는다.

## 5. 첫 지시

```bash
<skills>/herdr-flow/scripts/send.sh <이름> <<'EOF'
당신은 <작업 이름>의 하위 세션 <이름>입니다. 오케스트레이터는 <오케스트레이터 이름>입니다. 지시서 <지시서 절대 경로> 를 끝까지 읽고, 그 문서 「먼저 읽기」 순서대로 읽은 뒤 그대로 진행하세요. 답과 보고는 한국어로 씁니다. 단계마다 체크리스트 공유 기록(log)을 같은 턴에 쓰고, 끝나거나 막히면 <INBOX 절대 경로> 에 한 줄을 덧붙이세요(결정이 필요하면 [대기], 컨텍스트 60%를 넘으면 [인계 필요]). herdr로 오케스트레이터에게 직접 보고하지 마세요. 이 세션은 권한 확인이 뜨지 않는 모드이니 지시서의 「금지」와 「멈춤 조건」을 스스로 지키세요.
EOF
```

- codex 세션에는 영어로 지시하고 결과 파일 언어를 따로 정해 주면 안정적이다. 읽기 전용 리뷰면 「결과 파일 하나만 쓰고 다른 파일은 고치지 말 것」을 넣는다.
- `send.sh`가 `working`이 아니라고 하면 화면을 본다. 같은 지시를 다시 보내지 않는다.

## 6. 기록과 감시

같은 턴에:
1. 체크리스트가 있으면 `log`에 오케스트레이터 기록(`note`: 「<단계> 지시서 발송 → <이름>」). 단계 `start`는 하위 세션이 실제로 시작할 때 쓴다.
2. 인계 문서·체크리스트의 하위 세션 표에 이름·탭·맡긴 일 추가.
3. INBOX 감시가 아직 안 걸려 있으면 `herdr-flow-verify` 1절대로 건다(Monitor 한 번).

사용자에게는 짧게: 지시서 경로, 세션 이름·모델, 준비/실행 중 어디까지 맡겼는지, 다음 보고가 언제쯤 올지(하위 세션이 적은 목표 시각이 있으면).

## 7. 지시 변경·추가 지시

같은 세션에 범위를 바꾸거나 승인된 실행을 보낼 때:
1. **지시서 파일을 먼저 고친다**(바뀐 줄에 시각과 사용자 원문). 다음 세션도 같은 파일을 읽는다.
2. 보낼 문장: `[<오케스트레이터 이름> HH:MM] <무엇이 바뀌었나>. 사용자 원문: HH:MM 「…」. 지시서 <절 이름>을 고쳤습니다. 다시 읽고 <할 일>. <허용 범위 밖은 하지 마세요>.`
3. 실행 승인 전달은 한 줄: `[<오케스트레이터> HH:MM] <단계> 실행. 사용자 원문: HH:MM 「…」. 지시서 [실행] 순서대로 진행하세요.`
4. 체크리스트 `decisions`에 원문 기록, `log`에 note.
