# herdr-flow 공용 규칙

herdr-flow 스킬 묶음(`herdr-flow-*`, `herdr-handoff`)이 모두 따른다. 오케스트레이터가 하위 세션 지시서에 옮길 규칙은 「지시서에 넣을 것」 표시가 있다.
전역 규칙(`~/.claude/CLAUDE.md`, `~/.claude/rules/` 등)은 모든 세션에 자동으로 들어가니 다시 옮기지 않는다.

## 1. 역할

| 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 사람(사용자) | 목표·결정·승인, 체크리스트로 진척 확인 | 하위 세션 감시 |
| 오케스트레이터 | 목표 설정·분석·설계·계획, 지시서 작성, 하위 세션 기동·정리, 보고 직접 대조, 체크리스트 갱신, 사용자에게 보고·승인 질문 | 코드·AWS·k8s·DB를 직접 바꾸기(조회는 직접 한다) |
| 하위 세션 | 지시서 한 장의 일, 결과 파일·INBOX 한 줄·체크리스트 기록 | 지시서 밖의 일, 사용자에게 직접 묻기 |

## 2. 세션

- **새 세션은 새 탭으로 연다.** `pane split`은 쓰지 않는다(좁으면 Enter가 안 먹은 일이 있었음). `scripts/spawn.sh`를 쓴다.
- **권한 모드는 yolo(`cc`)가 기본이다.** `agent start … -- --dangerously-skip-permissions`가 막히면 `pane run <pane> "cc"` + `agent rename`(spawn.sh가 이 방식). auto 모드로 바꿔 띄우지 않는다. 사용자가 모드·모델을 지정하면 그대로.
- **모델**: 구현·조사·배포는 `claude`(Opus), 설계 토론·문서 수정은 사용자가 지정하면 `fable`, 외부 리뷰는 `codex`. 하위 에이전트·세션에 Haiku는 쓰지 않는다.
- **이름**: `<작업 약어>-<역할>[-번호]`. 오케스트레이터 `<약어>-orch-N`(인계마다 +1), 하위 세션은 단계 ID(`proj-s612`), 재작업·같은 단계 다른 세션은 `b`·`c` 접미사.
- **일 마친 세션은 바로 닫는다**(`scripts/close.sh <이름> <작업 트리>`). 인계를 받으면 쉬는 세션부터 정리한다. 사용자가 만든 탭, 자기 탭은 닫지 않는다.
- **herdr 명령은 샌드박스 밖**에서 실행한다(소켓 `Operation not permitted`).

## 3. 컨텍스트

`scripts/ctx.sh [접두사]`로 잰다(1M 토큰 창 기준. 창이 다른 모델은 토큰 수를 같이 본다).

| 대상 | 기준 |
|---|---|
| 하위 세션에 새 일을 주기 전 | 50% 넘으면 새 일은 새 세션에 |
| 일하는 하위 세션 | 60% 넘으면 진행 중 단계만 끝내고 INBOX에 `[인계 필요]` (지시서에 넣을 것) |
| 오케스트레이터 자신 | 70% 넘기 전에 `herdr-handoff` |

인계를 받자마자, 지시를 보낼 때마다 잰다.

## 4. 보고 — INBOX 한 줄 (지시서에 넣을 것)

- 하위 세션은 작업 폴더 `reports/INBOX.md`에 한 줄을 **덧붙인다**. 형식:
  `- YYYY-MM-DD HH:MM KST [세션 이름] <단계 ID> <끝|준비 끝|회차|판정|…> → <결과 파일>: <결론 한두 문장>. <다음>. 컨텍스트 NN%`
- 사용자 결정이 필요해 멈출 때: 줄 앞에 `[대기]`, 물을 것과 선택지별 결과를 한 줄에.
- 60%를 넘었을 때: `[인계 필요]`.
- **herdr로 오케스트레이터에게 직접 알리지 않는다.** 사용자가 오케스트레이터 탭에서 직접 타자를 치므로 입력에 섞인다. 예외는 운영 장애와 되돌리기를 실행했을 때뿐.
- 시각은 `date '+%Y-%m-%d %H:%M'` KST로 그 순간 읽은 값만.
- 오케스트레이터는 `scripts/inbox-watch.sh`를 **Monitor로 한 번** 걸어 받는다. 화면 끝 grep·idle 폴링·10분짜리 until 루프를 다시 거는 방식은 쓰지 않는다.
- 감시는 하위 세션이 실제로 일하는 동안만. 모두 사용자 결정 대기면 감시를 멈춘다. 트래픽 없는 dev는 시험 결과를 확인하면 바로 다음 단계로 간다(시간 감시는 운영만).

## 5. 체크리스트 기록 (지시서에 넣을 것)

- 작업에 `work-checklist`가 있으면 단계마다 공유 DB `log`에 **같은 턴에** 쓴다: 실제로 시작할 때 `start`, 멈추면 `block`, 끝나면 바로 `done`. `note`·`check`만 쓰면 완료로 안 보인다.
- 예약·대기 중인 일은 미리 `start`를 쓰지 않는다.
- 오케스트레이터가 직접 한 일(결정 기록, 직접 조회 결과, 지시서 변경)도 같은 턴에 `log`·`decisions`에 쓴다.
- 단계 추가·범위 변경이 생기면 그 턴에 `checklist.json` 수정 → 재생성 → 같은 경로 재게시 → `history` 행.
- 사용자에게 진척을 보고하기 전에 `log`를 query해 하위 세션 기록과 대조한다.

## 6. 사실과 대조

- 사용자에게 올리는 사실은 이 세션에서 직접 읽거나 실행한 것만. 하위 세션 보고는 「보고」라고 밝히고, 결정에 쓰이는 것은 **같은 폭으로 직접 대조한 뒤에** 올린다. 보고가 인용한 `파일:줄` 하나 열어 보는 것은 대조가 아니다.
- 「확인했습니다」에는 확인 범위를 붙인다. 못 본 것은 `미확인`과 확인 방법.
- 하위 세션의 「경로 없음」「불가」 보고는 그대로 올리지 않는다. 직접 확인한다.
- 대조 폭: 양쪽(이전·이후, 부르는 쪽·받는 쪽), 실행 구조(동시 실행·재시도·예약 작업 — 서버가 스스로 도는 cron 포함), 연결이 살아 있는지, 배포된 설정, 운영 데이터.

## 7. 결정과 승인

- **한 메시지에 결정 하나.** 승인이 필요한 것은 그것 하나만 따로 묻는다. 대기 항목·참고를 승인 질문 옆에 늘어놓지 않는다.
- **승인은 사용자가 그 일을 지목해 말할 때만.** 「진행」「넘어가자」를 게이트 승인으로 추측하지 않는다. 모호하면 어느 일을 승인하는지 묻는다.
- 선택지는 예시로 제시하고, 각 선택지의 결과(무엇을 얻고 잃는지)를 한 줄씩. 추천이 있으면 이유와 함께.
- 결정은 사용자 원문과 시각으로 기록한다(체크리스트 `decisions`, 인계 문서). AI가 「하겠습니다」라고 하고 사용자가 반대하지 않은 것은 결정이 아니다.
- 승인은 그 일 한 번만. 다음 일·바뀐 일·다음 세션으로 넘어가지 않는다. 사용자가 계속 허용한다고 말한 범위(예: 되돌리기 위임, 특정 PR `--admin`)만 원문·날짜와 함께 이어 간다.
- 사용자가 말한 시각·일정을 기준으로 잡는다. 미루려면 막힌 이유를 먼저 말한다. 정각 회차 같은 실제 제약이 없으면 시각을 고집하지 않는다.
- 사용자가 잠들기 전 등 「승인할 것 모아 말해 달라」고 하면 목록으로 주되, 줄마다 무엇을 하는지·되돌리기를 적고 사용자가 줄을 지목해 승인하게 한다.

## 8. 지시서 (자세한 틀은 `herdr-flow-brief`)

- 사용자가 정한 기준·지시는 **원문 그대로** 붙인다. 자기 말로 바꾸지 않는다.
- 합의된 설계와 한 줄씩 대조한 뒤 보낸다. 기존 코드 재사용 편의로 합의를 바꾸지 않는다.
- 합의 밖의 새 의존(저장소·Redis·테이블·외부 서비스)이나 동작 변경은 지시서에 넣기 전에 사용자에게 선택지로 묻는다. 현재 동작을 그대로 유지하는 선택은 묻지 않고 지시서에 넣고 보고만 한다.
- 계획에서 나눈 묶음이 작업 단위다. 독립 묶음은 하위 세션을 나눠 동시에 돌린다.

## 9. 말투

- 사용자에게 보내는 말과 하위 세션 지시·보고는 한국어.
- 맨 식별자(단계 ID, 결정 번호)는 내용을 먼저 쓰고 괄호에.
- 막힌 것인지 안 한 것인지를 첫 줄에 구분해 쓴다.
