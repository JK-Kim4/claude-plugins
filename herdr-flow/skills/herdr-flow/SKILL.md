# herdr-flow 진입점

이 디렉터리(`<skills>/herdr-flow/`)는 진입점 스킬이면서 묶음 전체가 쓰는 공용 규칙(`shared/`)·스크립트(`scripts/`)를 담는다. `<skills>`는 이 디렉터리의 부모다(플러그인 설치면 `<plugin>/skills`).

먼저 읽을 것: `shared/rules.md`(전부), `shared/folder-layout.md`.

## 1. 어디서 도는지 확인

```bash
test "${HERDR_ENV:-}" = 1 && echo herdr || echo "herdr 밖"
```

- herdr 밖이면: 작업 폴더·계획·결정은 할 수 있지만 하위 세션을 띄우거나 감시할 수 없다. 사용자에게 한 줄로 알리고, 하위 세션이 필요한 단계에 닿으면 herdr 패널 안에서 다시 시작하자고 한다.
- herdr 명령과 `scripts/*.sh`(herdr를 부르는 것)는 샌드박스 밖에서 실행한다.

## 2. 작업 폴더 찾기

1. 위치 규칙: 사용자 메모리·`CLAUDE.md`에 작업 폴더 규칙이 있으면 그것, 없으면 `folder-layout.md` 「위치」.
2. 인자나 대화에 작업 이름·티켓·경로가 있으면 그 이름으로 찾는다(`ls <작업 폴더 상위>`, 대소문자 무시 `find -iname`). 같은 티켓·주제 폴더가 있으면 새로 만들지 않는다.
3. 후보가 여럿이면 폴더 이름과 `plan.md` 첫 줄(상태)을 보여 주고 하나를 고르게 한다.
4. 없으면 새로 만든다(`folder-layout.md` 「새로 만들 때」의 명령). 처음 한 번은 위치를 사용자에게 확인한다. 만든 뒤 3절을 건너뛰고 `herdr-flow-plan`으로 간다.

## 3. 현황 읽기 (이미 있는 작업)

쓰기 직전에 원천에서 읽는다. 앞 세션 기억이나 인계 문서 값을 그대로 옮기지 않는다.

| 읽을 것 | 무엇을 뽑나 |
|---|---|
| `HANDOFF.md` | 지금 단계, 다음 한 걸음, 열린 질문. 0절 「먼저 읽을 것」과 1절 「사용자가 말한 것」은 끝까지 읽는다 |
| `plan.md` | 의도·완료 기준, 단계 표(페르소나·상태), 다루지 않을 것 |
| `decisions.md` | 마지막 결정 3개(번호·내용·사용자 원문) |
| `reports/INBOX.md` | 마지막 10줄. `[대기]`·`[인계 필요]`·`막힘` 줄 |
| 체크리스트(`checklist/`) | 공유 기록 `log`에서 단계별 마지막 상태 계산(마지막 `start`/`done`/`block`). 진행 중·막힘·대기 단계 |
| 하위 세션 | `scripts/ctx.sh <작업 약어>-` (이름·상태·컨텍스트 %), `herdr agent list` |
| 저장소·PR·배포 | 단계 표나 인계 문서에 적힌 것만: `git -C <repo> status -sb`, `gh pr view … --json state` 등 |

- 하위 세션이 `working`인데 INBOX 감시가 안 걸려 있으면 `herdr-flow-verify` 1절대로 건다.
- 인계를 막 받은 오케스트레이터면 자기 컨텍스트도 잰다(`rules.md` 3절). 쉬는 하위 세션이 있으면 `herdr-flow-close` 2절 기준으로 정리를 제안한다.

## 4. 현황 보고 — 한 화면

```
<작업 이름>(<티켓>) — 지금 <단계 이름>(<단계 ID>), 상태 <진행/대기/막힘>
- 끝난 단계 n / 전체 n. 진행 중: <단계 내용(ID) — 세션 이름·페르소나·컨텍스트 %>
- 사용자 결정 대기: <있으면 질문 하나와 선택지별 결과>
- 마지막 결정: <내용(D-n)>
확인 범위: <읽은 원천> / 미확인: <못 읽은 것과 이유>
다음: <한 걸음> — <쓸 스킬>
```

- 사용자 결정 대기가 있으면 그것 하나를 마지막에 묻는다. 다른 대기 항목을 옆에 늘어놓지 않는다.
- 숫자에는 센 기준을, 상태에는 읽은 시각을 붙인다.

## 5. 다음 한 걸음 고르기

| 상황 | 다음 스킬 |
|---|---|
| 새 작업, 또는 `plan.md`에 범위·단계가 비어 있음 | `herdr-flow-plan` |
| 설계 갈림길이 열려 있고 사용자가 토론·외부 리뷰를 원함 | `herdr-flow-debate` |
| 계획 승인이 끝났고 다음 단계가 대기 | `herdr-flow-brief`(단계 표의 페르소나로) |
| 하위 세션이 일하는 중 / 보고 줄이 와 있음 | `herdr-flow-verify` |
| 「준비 끝」이 와서 실행 승인이 필요함, 되돌리기 어려운 일 직전 | `herdr-flow-gate` |
| 단계가 모두 끝남 | `herdr-flow-close` |
| 오케스트레이터 컨텍스트 70% 근처 | `herdr-handoff`(사용자가 `/herdr-flow:herdr-handoff`로 부름) |

한 번에 하나만 제안한다. 사용자가 고르면 그 스킬을 불러 이어간다.
