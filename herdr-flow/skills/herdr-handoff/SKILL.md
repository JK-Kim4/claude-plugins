# Herdr 세션 핸드오프

`<skills>`는 이 스킬 디렉터리의 부모다(로컬 설치면 `~/.claude/skills`, 플러그인 설치면 `<plugin>/skills`). `herdr-flow/`는 공용 규칙·스크립트만 담은 형제 디렉터리다.

지금 세션은 컨텍스트가 거의 찬 상태다. 이 스킬을 쓰는 동안에도 컨텍스트를 아껴라. herdr 스킬은 따로 불러오지 않는다. 여기 없는 herdr 명령이 필요할 때만 불러온다.

**Herdr 명령은 샌드박스 안에서 소켓이 막혀 `Operation not permitted`가 난다.** 이 스킬의 herdr 명령과 스크립트는 샌드박스 밖(`dangerouslyDisableSandbox: true`)에서 실행한다.

herdr-flow 작업(오케스트레이터·하위 세션)이면 `<skills>/herdr-flow/shared/rules.md`를 따른다. 세션 기동·컨텍스트 측정은 그 묶음의 `scripts/spawn.sh`·`scripts/ctx.sh`를 쓴다.

## 1. 요청 읽기

사용자 요청과 인자에서 아래를 뽑는다. 없는 항목은 기본값을 쓴다.

| 항목 | 기본값 | 예 |
|---|---|---|
| 이 세션에서 먼저 끝낼 일 | 없음 | "10곳 재배포까지 하고 넘겨" → 그 일을 끝낸 뒤 2단계로 간다 |
| 새 세션이 할 일 | 인계 문서의 '다음 할 일' | "배포 단위 분리 작업", "14:00 배포 이어서" |
| 시작 방식 | 요약 후 대기 | "바로 이어서 진행", "작업 지시까지" → 대조 후 착수 지시(7단계) |
| 새 세션 역할 | 이 세션과 같은 역할 | "오케스트레이터로, 구현은 또 새 탭에 지시" |
| 새 세션 이름 | 이 세션 이름의 번호 +1 (`proj-orch-10` → `proj-orch-11`, 하위 세션 `proj-s612` → `proj-s612b`) | "orch-12로" |
| 모델 | `claude`(Opus) | "fable로", "sonnet으로" |
| 같이 넘길 자료 | 없음 | artifact 링크, 체크리스트, 설계 문서 |

## 2. 상태 모으기

```bash
<skills>/herdr-handoff/scripts/context.sh
```

`herdr_env=0`이 나오면 Herdr 패널 밖이니 사용자에게 알리고 멈춘다. 출력의 `cwd`, `taken_names`, `transcript`, `now`를 이후 단계에 쓴다.

오케스트레이터면 하위 세션 컨텍스트도 잰다(인계 문서 하위 세션 표에 넣는다):

```bash
<skills>/herdr-flow/scripts/ctx.sh <작업 약어>-
```

## 3. 인계 문서 위치

1. **이 작업의 작업 폴더가 이미 있으면 그 안에 쓴다.** `HANDOFF.md`, `PROGRESS.md`, `notes/`가 있는 폴더다.
   - 앞 세션 인계 문서가 이미 있으면 파일을 새로 늘리지 않는다. 지금 `HANDOFF.md`를 `notes/<YYYY-MM-DD>-<앞 이름>-인계-<이 세션 이름>.md`로 옮긴 뒤, `HANDOFF.md`를 지금 기준으로 다시 쓴다(지난 상태·이미 끝난 계획은 지운다). 옮긴 문서의 「사용자가 말한 것」 절은 새 문서 0절 읽을 목록에 넣는다.
   - 그 폴더의 `HANDOFF.md`가 결정 기록·진행의 정본이면 그 문서의 '현재 상태'만 갱신한다. 대화에만 있던 내용은 `notes/<YYYY-MM-DD>-세션-인계.md`에 쓴다.
2. **작업 폴더가 없으면 새로 만든다.**
   - 위치는 `<skills>/herdr-flow/shared/folder-layout.md`의 「위치」 규칙(사용자 메모리·CLAUDE.md 규칙이 먼저)을 따르고 `HANDOFF.md`로 만든다.
3. git 저장소 작업 트리(커밋 대상) 안에는 쓰지 않는다.

## 4. 라이브 상태 다시 읽기

인계 문서에 적을 상태 값은 쓰기 직전에 원천에서 다시 읽는다. 세션 기억으로 쓰지 않는다.

- 건드린 저장소마다: `git -C <repo> status -sb`, `git -C <repo> log --oneline -3`, push 안 한 커밋, stash
- 열린 PR: `gh pr view <번호> --repo <owner/repo> --json state,headRefOid,mergeable,url`
- 배포·파드·설정·데이터: 문서에 적을 항목만 그 원천에서
- **이 세션이 띄운 백그라운드 작업(`run_in_background`, Monitor, ScheduleWakeup, CronCreate)은 새 세션으로 넘어가지 않는다.** 계속 필요하면 새 세션이 다시 거는 방법을 문서에 적는다.
- 이 세션이 지시하던 다른 Herdr 에이전트가 있으면 이름·패널 ID·맡긴 일을 적는다.

다시 못 읽은 값은 `미확인`으로 적는다.

## 5. 인계 문서 쓰기

**핵심은 대화에만 있던 것이다.** 정본 문서(HANDOFF·PROGRESS·설계 문서·Jira)에 이미 있는 내용은 경로와 절만 가리키고 복사하지 않는다. 보통 50~120줄이다. 더 길어지면 정본 문서로 옮길 내용이 섞인 것이다.

```markdown
# 세션 인계 (<YYYY-MM-DD HH:MM>, <앞 세션 역할> → <새 세션 역할>)

이 문서는 앞 세션 대화에만 있던 내용을 남긴 것이다. 상태의 정본은 <정본 문서 경로들>이고, 이 문서와 다르면 그쪽이 맞다. 앞 세션 원본 대화: `<transcript>`(필요할 때만 검색).

## 0. 먼저 읽을 것 (순서)
## 1. 이 세션에서 사용자가 말한 것 (원문, 같은 실수 금지)
## 2. 지금 상태 (<HH:MM> 확인)
## 3. 확정된 결정 (다시 묻지 말 것)
## 4. 사용자 결정 대기
## 5. 다음 할 일
## 6. 시도했다 버린 것
## 7. 작업 요령 (이 머신에서 확인한 것)
## 8. 지킬 규칙 (yolo 모드라 권한 확인이 뜨지 않는다)
```

절마다 쓸 것:

- **0 먼저 읽을 것**: 이 문서 → 지난 인계 문서의 「사용자가 말한 것」 절 → 정본 문서(읽을 절까지) → 같이 넘길 자료 → 관련 메모리 이름. 경로는 절대 경로.
- **1 사용자가 말한 것**: 이 세션에서 사용자가 지적·정정·질책한 말을 시각과 원문으로, 줄마다 `→ 앞으로 할 것` 한 줄. 지난 인계까지의 지적은 옮기지 않고 0절에서 가리킨다. 마지막 줄에 계속 유효한 원칙(예: 한 메시지에 결정 하나, 값은 실측, 하위 세션 보고는 대조한 것만, 하위 60%·오케스트레이터 70% 인계)을 한 줄로.
- **2 지금 상태**: 저장소·브랜치·SHA·PR·배포·데이터 상태, 진행 중인 백그라운드 작업. 값마다 확인 시각이나 원천. 오케스트레이터면 **하위 세션 표**(세션 이름 · 탭/패널 · 컨텍스트 % · 상태·맡긴 지시서)와 닫은 세션 목록.
- **3 확정된 결정**: 결정, 이유, 누가 언제 정했는지(사용자 말이면 짧게 인용). 이유가 빠지면 새 세션이 같은 질문을 다시 한다.
- **4 사용자 결정 대기**: 사용자가 답할 질문과 선택지별 결과 한 줄씩.
- **5 다음 할 일**: 순서 있는 목록. 1단계에서 받은 '새 세션이 할 일'을 넣는다. 첫 항목은 바로 실행할 수 있게 파일·명령까지 적는다.
- **6 시도했다 버린 것**: 막힌 방법과 이유. 새 세션이 같은 길을 다시 가지 않게 한다.
- **7 작업 요령**: 샌드박스 밖에서 돌려야 하는 명령, 접속 방법, 빌드·테스트·렌더 명령, 이 머신에서 겪은 함정.
- **8 지킬 규칙**: 이 작업에서 허용된 범위와 금지된 것만 쓴다. 전역 규칙(`~/.claude/CLAUDE.md`, `~/.claude/rules/`)은 새 세션에도 자동으로 들어가니 다시 옮기지 않는다.
  - **승인은 이월하지 않는다.** 이 세션에서 받은 1회 승인(운영 쿼리, 배포, 비용 작업 등)은 '실행 완료'로만 적는다. 사용자가 계속 허용한다고 말한 범위만 원문 인용과 날짜를 붙여 적는다.

문장 규칙:

- 맨 식별자를 쓰지 않는다. 내용을 먼저 쓰고 번호·키는 괄호에 둔다. 새 세션이 그대로 사용자에게 옮긴다.
- 조건을 사실과 함께 둔다. 추정은 `추정`, 확인 못 한 것은 `미확인`으로 적는다.
- "그거", "아까 그 방식"처럼 대화를 봐야 풀리는 말을 남기지 않는다.
- 비밀 값은 쓰지 않는다. 위치(Secret 이름, 파일 경로)만 쓴다.

다 쓰면 대화를 모르는 사람처럼 한 번 읽는다. 대화 없이 5절 첫 항목을 실행할 수 없으면 고친다. 이 작업의 프로젝트 메모리가 있으면 인계 문서 경로와 지금 상태 한 줄로 갱신한다. 작업 폴더 README가 노트 목록을 두고 있으면 거기도 반영한다.

이 문서는 다음 세션(에이전트)이 읽는 작업 노트다. doc-writing 스킬의 리뷰·렌더 단계는 하지 않는다.

## 6. 새 탭과 yolo 세션 열기

```bash
<skills>/herdr-flow/scripts/spawn.sh <새 이름> <claude|fable|sonnet> "" "<cwd>"
```

- **새 탭으로 연다.** 패널을 나누지 않는다(좁은 패널에서 Enter가 안 먹은 일이 있었음). 워크스페이스는 이 세션과 같은 곳(인자 비움).
- **yolo(`cc`)로 띄운다.** spawn.sh가 `pane run "cc"` + `agent rename`으로 띄운다. auto 모드로 바꿔 띄우지 않는다.
- **cwd는 이 세션과 같게 둔다.** Claude Code의 프로젝트 메모리와 설정은 cwd 기준이라, 바꾸면 새 세션이 다른 메모리를 읽는다.
- 이름은 1단계에서 정한 것. `이미 있는 이름`이 나오면 다음 번호.
- `idle 대기 실패`(시작 중 확인 화면에 멈춤): 출력된 화면을 사용자에게 알린다. 확인 화면에 임의로 답하지 않는다.
- spawn.sh를 못 쓰는 환경이면: `herdr tab create --workspace <ws> --cwd "<cwd>" --label <이름>` → `.result.root_pane.pane_id` → `herdr pane run <pane> "cc"` → 에이전트가 잡히면 `herdr agent rename <pane> <이름>`.

## 7. 첫 지시와 요약 대조

**시작 방식과 관계없이 첫 지시는 '읽고 요약한 뒤 대기'다.** 요약을 대조하고 나서야 착수를 지시한다.

```bash
<skills>/herdr-flow/scripts/send.sh <새 이름> <<'EOF'
<작업 이름>(<Jira 키>)의 <역할>을 앞 세션(<앞 이름>)에서 이어받는 새 세션입니다. 당신의 herdr 이름은 <새 이름>입니다. 앞 세션은 컨텍스트 <NN>%라 인계했습니다. 먼저 <인계 문서 절대 경로> 를 끝까지 읽고, 그 문서 0절 순서대로 나머지를 읽어 주세요. <역할이 오케스트레이터면: 역할은 오케스트레이터입니다(구현·조사·배포는 herdr 하위 세션에 지시서로 맡기고, 결과를 원천으로 직접 대조한 뒤 사용자에게 보고). herdr-flow 스킬 묶음과 <skills>/herdr-flow/shared/rules.md를 따르세요.> 다 읽으면 (1) 지금 상태, (2) 사용자 결정 대기, (3) 이 세션이 다음에 할 일을 한국어로 짧게 요약하고 지시를 기다려 주세요. 그 전에는 읽기 말고 다른 작업을 하지 마세요. 반드시 지킬 것: 인계 문서 1절(사용자가 말한 것)과 8절(지킬 규칙). 이 세션은 권한 확인이 뜨지 않는 모드입니다. <사용자가 이 탭에서 직접 대화하면: 사용자는 당신 탭에서 직접 대화합니다.>
EOF
herdr agent wait <새 이름> --until idle --timeout 600000
herdr agent read <새 이름> --source recent-unwrapped --lines 150
```

- `send.sh`가 working이 아니라고 해도 같은 지시를 다시 보내지 않는다. 화면을 본다.

이 세션이 아는 것과 대조한다. 지금 상태가 틀렸는지, 사용자 결정 대기가 빠졌는지, 다음 할 일이 어긋났는지, 허용 범위를 넓게 읽었는지(예: 운영 작업이 허용됐다고 이해) 본다.

- **틀린 곳이 있으면 인계 문서를 먼저 고친다.** 다음 세션도 같은 문서를 읽는다. 그다음 정정 지시를 보낸다: "인계 문서의 <절 이름>을 고쳤습니다. 다시 읽고 <무엇>을 정정해 주세요." 최대 두 번. 그래도 어긋나면 사용자에게 보고한다.
- 시작 방식이 '바로 진행'이면 대조가 끝난 뒤 착수를 지시한다(`--wait` 없이).

```bash
<skills>/herdr-flow/scripts/send.sh <새 이름> <<'EOF'
요약이 맞습니다. 인계 문서 5절 '다음 할 일'의 첫 항목부터 진행하세요. 사용자 결정이 필요한 지점에 닿으면 멈추고 하나만 물어보세요.
EOF
```

### 오케스트레이터 인계면 추가로

1. **하위 세션에 새 이름을 알린다.** 일하는 하위 세션마다 한 줄: `[<앞 이름> → <새 이름>] 오케스트레이터가 <새 이름>으로 바뀌었습니다. 보고는 그대로 INBOX에, 되돌리기 직접 보고만 <새 이름>에게.` (`send.sh`)
2. **이 세션이 건 백그라운드 감시(Monitor, run_in_background, wake-at)는 넘어가지 않는다.** 인계 문서 5절 첫 항목에 「INBOX 감시 다시 걸기(`herdr-flow-verify` 1절), 정해진 시각 깨우기 <시각·할 일>」을 적었는지 확인한다. 이 세션의 감시는 새 세션 대조가 끝난 뒤 멈춘다(TaskStop).

## 8. 사용자에게 보고

짧게 알린다.

- 인계 문서 경로(절대 경로), 옮긴 지난 인계 문서 경로
- 새 세션 이름, 탭, 모델
- 요약 대조 결과: 일치했는지, 고친 곳이 있으면 무엇을
- 새 세션 상태: 지시 대기 중인지, 착수했는지. 오케스트레이터면 하위 세션 알림을 보낸 세션 목록
- 포커스는 옮기지 않았다. 원하면 `herdr agent focus <이름>`으로 옮긴다.

인계가 끝나면 이 세션은 같은 작업 파일을 더 고치지 않는다. 두 세션이 같은 파일을 고치면 서로 덮어쓴다. 이 세션의 탭은 사용자가 닫으라고 하면 답을 보인 뒤 닫는다(`Bash(run_in_background) sleep 30; herdr tab close <이 탭 ID>`).

## 하지 않는 것

- 사용자가 만든 탭을 닫기, 사용자 말 없이 이 세션 탭을 닫기
- `pane split`으로 패널 나누기, auto 모드로 띄우기
- `claude --resume`, `--fork-session`으로 옛 대화를 통째로 넘기기. 컨텍스트가 찬 채로 넘어간다.
- 새 세션 cwd 바꾸기, 새 워크스페이스·worktree 만들기(사용자가 요청할 때만)
- 새 세션의 확인 화면(`blocked`)에 임의로 답하기
- 지시가 안 들어간 것 같다고 같은 프롬프트를 다시 보내기
