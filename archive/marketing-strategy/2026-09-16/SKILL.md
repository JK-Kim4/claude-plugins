# marketing-strategy — 마케팅 전략 수립

마케팅 주제를 받아 검증된 전략 문서를 만든다. 2026-08-19 리텐션·유입 작업에서 실증된 흐름의 전반부다.
**외부 스킬 웹 조사·clone 은 파이프라인에 없다** — 필요한 프레임워크는 아래에 내장돼 있고, 실행은 로컬 자산 조합으로 한다. (새 주제가 내장 프레임워크로 부족할 때만 사용자에게 외부 조사를 별도 제안한다.)
산출물이 확정되면 `pm-breakdown` 스킬로 작업 분해·이슈화를 잇는다.

## 로컬 자산 조합

| 역할 | 자산 | 쓰는 지점 |
|---|---|---|
| 리텐션 프레임워크 | `retention-playbook` 스킬 (활성화·온보딩·이탈·운영 루프) | 초안 작성 — Skill 도구로 로드 |
| 유입 프레임워크 | `acquisition-playbook` 스킬 (공유 루프·가입 마찰·검색·국내 지형) | 초안 작성 — Skill 도구로 로드 |
| 시니어 마케터 페르소나 | fork 서브에이전트 + 역할 프롬프트 | 3단계 리뷰 |
| 요구사항·계획 보조 | `oh-my-claudecode:analyst` / `planner` (필요 시) | 주제가 넓어 사전 정리가 필요할 때 |
| 화면 결정 | `ux-mockup` 스킬 규율 | 터치포인트 목업·비교 목업 |
| 운영 DB 실측 | [[oci-db-readonly-access]] 메모리 경로 | 4단계 검증 |

## 프레임워크 로드

초안 작성 전 `retention-playbook`(활성화·온보딩·이탈·운영 루프 명세법)과 `acquisition-playbook`(공유 루프·가입 마찰·검색·국내 지형 체크리스트)을 Skill 도구로 로드한다 — 원본 오픈소스 스킬(marketingskills MIT·pm-skills Apache 2.0)을 소설비 맥락으로 번안한 증류본이며, 소설비 실측 확정값(활성화 정의·죽은 소스·채널 상태)도 담고 있다. 주제가 두 플레이북 범위를 벗어나면(예: 유료화·광고) 외부 원본 재조사를 사용자에게 별도 제안한다.

## 원칙

- **각 단계는 사용자 검토 게이트로 끝난다** — 다음 단계는 검토 응답 후 진행. 알림과 실행을 같은 턴에 합치지 않는다.
- **수치·정의는 실측 전까지 "가설"로 명시한다.** 확정처럼 쓰지 않는다 (금지 1·2).
- **화면이 걸린 결정은 텍스트 선택지 금지 — 비교 목업 먼저** (discipline §10). 결정의 핵심 상태(예: "쉬었다 돌아온 날")까지 그린다.
- 산출물은 `docs/research/YYYY-MM-DD-*.html` (검토용) — 반응형 SVG(`viewBox` + `width:100%`)로 스크롤 바 없이. 다이어그램은 별도 파일이 아니라 본문 섹션에 포함.
- 운영 DB 조회는 읽기 전용 집계만, 개별 사용자 값(이메일 등) 미조회.

## 단계

### 1. 전략 초안 + 목업

- 내장 프레임워크로 전략 초안 HTML 작성. 필수 구성: 활성화·지표 가설(검증 필요 명시) / 전략 항목별 근거 / 운영 루프 / 로드맵 / **열린 질문 목록**.
- 화면 터치포인트는 와이어프레임 목업 HTML 을 함께 작성하고 `open` 으로 띄운다. 와이어프레임은 배치 정본이 아님을 명기한다.
- 게이트: 두 문서 검토 요청.

### 2. 페르소나 리뷰 — 실질 효과 판정

- fork 서브에이전트에 시니어 페르소나(예: 15년차 국내 B2C 그로스 마케터)를 부여해 초안을 리뷰시킨다. 리뷰 관점을 프롬프트에 고정: 항목별 효과 예상 / 놓친 함정(§국내 지형 체크리스트) / ROI 기준 우선순위 조정 / 추가 제안. "추측 데이터를 사실처럼 쓰지 말 것" 지시 포함.
- 리뷰 결과로 우선순위를 재배열하고, 실행 차단 요소(도달 채널 등)는 Step 0 으로 승격한다.
- 게이트: 리뷰 전문 보고 → 반영 방향 확인.

### 3. 실측 검증 — 가설을 데이터로

- 전략의 전제(채널 보유율·활성화 퍼널·활동 규모)를 **읽기 전용 집계**로 실측한다. 코드 실측(스키마·인증 흐름 grep) → 운영 DB 집계 순.
- **프로브 결함 경계** (§19-5): 0·전무 같은 극단값은 소스가 죽었는지 다른 소스와 교차 검증한다 (예: `work_sessions` 는 2026-07-12 이후 미적재 — 활동 판정은 `documents.updated_at` + `attendance`).
- 결과는 문서에 절 추가로 기록.
