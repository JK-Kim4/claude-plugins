# retention-playbook — 소설비 리텐션 실무 참조

원 출처: coreyhaines31/marketingskills(MIT)의 `onboarding`·`churn-prevention`·`marketing-loops`를 정독 후 소설비 맥락(무료 서비스·소규모·핵심 행동=집필)으로 번안. 원본의 결제·dunning·할인 오퍼 절은 무료 서비스라 제외했다 — 유료화 도입 시 원본 재참조.

## 1. 활성화 (aha moment)

- 정의 질문: **"유지되는 사용자는 하고, 떠난 사용자는 안 한 행동이 무엇인가."** 가장 이른 재방문 예측 지표를 찾는다.
- 소설비 확정 정의(2026-08-19 실측): **가입 7일 내 첫 저장(word_count>0)**. 실질 승부는 첫날(작품 생성의 94%가 1일 내). 500자 분량 축은 GA4 적재 후 재평가.
- 지표: 활성화율 / 활성화까지 시간 / 단계 수 / 코호트·유입경로별 활성화.
- 퍼널은 단계별 낙폭을 보고 **가장 큰 낙폭에 집중**한다. 소설비 최대 낙폭(2026-08 실측): 작품 생성 66% → 첫 저장 38%.

## 2. 온보딩 설계 원칙

- **Time-to-Value 최소화**: 가입과 핵심 가치 체험 사이의 모든 단계를 제거 후보로 본다.
- **첫 세션 한 가지 목표**: 첫 세션은 "첫 문장 저장" 하나로. 고급 기능은 뒤로.
- **Do, Don't Show**: 튜토리얼보다 실제로 하게 한다.
- **진행의 가시화**: 진척 표시·완료 축하가 습관을 만든다. (소설비 확정: 연속 스트릭이 아니라 "주 N일" — 끊김이 복귀 장벽이 되는 역효과 회피, #152)
- **빈 상태(empty state)는 온보딩 기회다**: 이 영역이 뭘 하는 곳인지 + 데이터가 있으면 어떤 모습인지 + 첫 항목을 만드는 단일 행동. 막다른 화면 금지.
- 체크리스트 패턴을 쓸 땐 3~7개·가치순·빠른 승리 먼저·닫기 가능.
- 이메일은 인앱 행동을 복제하지 말고 보강한다 — 제품으로 돌아오게 하는 구체 CTA 하나.

## 3. 이탈 감지·win-back

- 구분: 자발(흥미 상실·슬럼프) vs 비자발(잊음). 무료 서비스는 **핵심 행동 중단 = 이탈**.
- 위험 신호(원본 표를 소설비 데이터 소스로 번안):

| 신호 | 위험도 | 소스 |
|---|---|---|
| 집필일 빈도 절반 이하로 하락 | 높음 | `documents.updated_at` 주간 집계 |
| 14일 무저장 (이전 4주 활동 있음) | 높음 | 〃 |
| 출석은 하는데 저장이 없음 | 중간 | `attendance` vs `documents` 대조 |
| export 실행 직후 무활동 | 관찰 | 데이터 반출은 이탈 전조일 수 있음 |

- `work_sessions` 는 소스로 쓰지 않는다 — 2026-07-12 이후 미적재 확인된 죽은 소스.
- **win-back 원칙**: 판촉이 아니라 사용자의 산출물 기준 — "『작품명』이 n일째 기다리고 있어요 + 마지막 문장 미리보기". 죄책감 유발 문구 금지("우리를 버리시나요" 류). 채널: 이메일(보유·검증 100% 실측, 2026-08-19). 마케팅성 발송 전 수신동의 요건 확인.
- 고가치 사용자(다작·커뮤니티 활동)는 자동 발송보다 개별 관찰 — 현재 규모(수십 명)에선 전원 개별 관찰이 맞다.

## 4. 운영 루프 명세법 (marketing-loops 핵심)

루프 하나를 만들 때 9요소를 전부 채운다 — 하나라도 비면 자산이 아니라 부채다:

| 요소 | 내용 |
|---|---|
| 체크 주기 | 얼마나 자주 **보는가** — 신호가 실제로 변하는 속도에 맞춘다 |
| 발동 조건 | 무엇이 참일 때 **행동하는가** — 좋은 루프의 대부분 실행은 "확인만 하고 통과" |
| 목적 | 이 루프가 움직이는 단 하나의 지표 |
| 사용 스킬 | 각 반복에서 조합하는 다른 스킬 |
| 루프 본문 | 반복마다 도는 순서 있는 단계 |
| 자기검증 | 행동 **전** 검증 — 노이즈·계절성·계측 버그에 반응하지 않기 위해 |
| 상태/멱등성 | 실행 간 기억: 마지막 실행·중복 방지 키·쿨다운 — 없으면 같은 사람에게 두 번 보낸다 |
| 정지 조건 | 언제 건너뛰고·멈추고·사람에게 올리는가. "없음"은 답이 아니다 |
| 산출 | 결과가 가는 곳: 파일·대기열·알림 |

- 주기 기준표: 이탈 신호=일 1회 또는 트리거(개입 창이 짧다) / 활성화 퍼널=주 1회(표본 필요) / 콘텐츠 부식=월 1회 / 검색 순위=주 1회. **과도한 주기가 가장 흔한 실패** — 산출을 무시하도록 스스로를 훈련시킨다.
- 발송이 걸린 루프는 사람 승인 대기열을 거친다.

## 5. 소규모 단계 주의 (소설비 현 단계)

- 수십 명 규모에서 퍼센트 지표는 통계적 소음 — 개별 사용자 단위 관찰로 운영.
- 커뮤니티 챌린지류는 임계 인원 미달 시 "빈 방" 역효과 — 활성 규모 실측 후 판단.
- A/B 테스트는 표본이 안 나온다 — 실측·정성 관찰 우선.
